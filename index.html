挥剑、命中、挨打反应:三段门各有一批设备实物

机制全部从反编译的 z_boss_ganondrof.c / z_player_one.c 移植,不发明。几何:刀身线段 vs 本体 440 面,十台 PIN 孪生各钉一个攻击表行,副屏只印布尔量不印坐标。时序:七台各钉一条时间链(第一下 AirDamage+计时 50、反应中再挨 GroundDamage 且不重置、无敌 10 格吞 AC_HIT、到 0 回待机),BOSSWIND 把链冻在第 n 个动画 tick 才谈得上可复现。姿势:反应表三段逐帧与离线整数复刻同值,且"段 0 嫁接自 idle"由像素证明(那台上屏与在册待机帧 0 逐字节相同)。⚠ SWORDHIT/BOSSREACT/LINKSWORD 默认 0 —— 交付 ROM 目前还不会挥剑。

镜子翻过来:挨打的是林克

`LINKDMG=1`(默认 0)把 `z_player.c:4927`/`:4637`/`:4645`/`:4731`/`:4739` 那台吃伤状态机与 `z_parameter.c:2238-2281` 的血量算术搬进机内,十台 PIN 孪生逐格对账副屏那七个读数(`php h.. c.. i..` + `b.. k.. d.. a..`)。伤害数不是挑的:玩家没有 `damageTable` ⇒ 走 `tbl==NULL` 那支,`defense=0x00` ⇒ 本体两只圆柱原样落 16 与 48。击全部由 `LINKHITAT` **注入**(按下去的是同一条 `linkDamageStrike`,不是新机制),十台都自印 `hit 0 n 0` —— "这一片里没有真命中"是设备自己说的;真命中那一路(本体 AT 圆柱撞玩家 AC 圆柱)是反向体积判定,还没进门。⚠ `LINKHP`/`LINKHIT` 故意没有默认值,宁可编不过也不发明 ROM 里属于存档上下文的那个数。

一整场战斗:挥剑→扫中→摔落→死亡链

`FIGHT=1` 换一张十三段的分镜表(循环 600 屏帧),机制旋钮一个都不动 —— 注入点、朝向、步长、碰撞、判伤体积与相机全是同一条链,到完整移植那天这张表要么由人玩出来、要么由它自己演出来,用的是同一只手。交付物是一条宣传片(421 帧 · 512×384 · 编码帧率取本次实测交付速率,所以成片时长 == 真实墙钟)与两台逐位复现的机器:演这一场那台带 `BOSSHP=4`(血掉得完、死亡链走完),给离线预演对账那台不带它(本体活过整窗)。⚠ 起手那一下是编译期注入的激励,不是"林克打中了他";林克真的判中那一剑是另一件独立成立的事(副屏自印 `sw2 … h1`)。

预算:最坏可达机位占吞吐 9.6%

1,077,888 个可到达的机位里最坏 2128 面 / 6384 顶点 = 66,666 顶点每帧的 9.6%。纹理显存实测 22 段 / 66 KB / 零重叠。

硬上限不是瓶颈,CPU 才是 —— 已量到 39.4 sf/s

ARM946E-S 没有 FPU,逐顶点软浮点吃掉整帧 73%(本体那 440 面)。绘制路改定点/整数后周期锁定实测 25.4 ms/帧,与"摘掉本体"的 25.0 ms 只差 0.4 ms。三个旋钮默认 0,交付 ROM 仍是浮点通路 —— 翻它等的是人眼门:同钉帧逐像素差 173 个(0.352%),而按 PNG 整文件 md5 判,这 173 个全属整数光照 LITFIX,提交位宽那半一位像素都不动。

这个项目是什么 ​

把《塞尔达传说 时之笛》N64 原版 ROM 里森林神殿的幻影加农 boss 房(moribossroom)移植到 Nintendo DS: 房间几何、纹理、碰撞、透视相机与 Link 的可行走,全部跑在 DS 那套固定函数硬件管线的约束下 (顶点色 + CI4/CI8 纹理、无浮点、无 per-poly z-write、顶点吞吐有硬上限)。

起点是裁剪版:静态场景 + 本体静态网格 + Link 可行走 —— 这部分已交。2026-10-11 把终点扩成做一场能演示的 boss 战斗:持剑/命中/挨打反应、血量与死亡链、本体位移机、以及一整圈自导剧本(FIGHT=1)都已收口,交付物是一条宣传片。仍不做:跨房间 exit、水/WaterBox、 bgCam 分区变相机、N64 原版参考截图管线。

本体身份钉死过一条误判:object_sst 是 Bongo Bongo(影之神殿),幻影加农是 actor type 0x52 → object_gnd,Standard 骨架而不是 Flex ⇒ 运行时正向运动学(FK)不在本场景的依赖里。
