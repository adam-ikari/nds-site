还欠什么 ​

  1. 人眼判决（协议 3）没收到。数字门全部通过后，"这就是森林 boss 房、纹理是对的、比例是对的"这一句 必须由人看图判定，量具不代替它。素材在 画面证据 的前两节（验收 ROM 三张 + 七张拼图）， 其中 contact_sheet_2026-10-05_final.png 是终检图：四格各只问一件事（整场景 / 本体被 Link 挡住 像不像 / 走到位后比例与四肢 / 转的是相机不是重画场景），一票判完不必翻其余六张分项。
  2. 偏差 4 会被人看见：本轮按计划不做相机碰撞，房间小、CAM_DIST=90 而眼高只有 60 ⇒ 5975 个合法站立格里 四个朝向各有 50~55% 让眼点落进极近几何档，那个档里量具与真机对不齐（色场 WARN 的来源）。
  3. 偏差 1 的归属未证：desmume 相对 CPU 量具的屏幕错位不是恒定 +3px（y180 最优是 dx=0）， 本体那四个独立读数倒是都落在 dx=2。glGetFixed 回读在 desmume 上不响应 ⇒ 上真机第一件事就是复测这条。
  4. 本体角色纹理仍以决定为由关掉：draw_boss.c 只走顶点色 + 白纹理单位元，所以幻影加农在画面里发白。 object_gnd 的骨架可达 limb DL 里实测有 51 SETTIMG / 51 LOADBLOCK / 51 SETTILESIZE / 102 SETTILE / 52 SETCOMBINE （且这是下界：每条 limb DL 那条外部段 G_DL 按既有口径不递归），要补得走与房间同套管线的另一份口径。 Link 那侧已经不在这一条里了：src_scene/link_rigid.c 的 LINKTEX 默认值为 1（2026-10-08 转正，见下面那节）， 验收 ROM 里的林克带真纹理。两条的完整口径与实测数在 已知偏差 偏差 2。 ⚠ 本页此前抄的是「190 / 97 / 54」，那是整镜像朴素 opcode 直方图把数据字节数成命令的结果，已由 docs §5 更正。
  5. 偏差 5 也会被人看见：把 Link 走到竞技场沿上，他站住不动而不是掉下去 —— 本轮不做重力，落点的地板 探测窗口是 [feetY, feetY+6]（src_scene/main.c:605，下界正好等于当前脚底），所以任何比当前脚底低的地面 一律被拒、整次移动作废。计划 S5 只要求"站在地面、撞墙不穿"，没要求 fall 状态，所以这是裁剪口径而不是 地板解漏了多边形。图上认这条看的是副屏坐标数字停住、walk 那对极值不再扩大，不是状态词 —— 截图前必然松键， 而 moveState 每帧在按键检查前复位，存档图里那个词恒为 idle（[feetY, feetY+6] 这条窗口的实测范围与配方在 已知偏差 偏差 5）。
  6. 交付 ROM 走的还是浮点绘制通路（S9/S10，2026-10-10，读数 2026-10-11 重造）：定点/整数那条路已经把整帧从 84.3 ms 压到 25.4 ms （desmume 侧、周期锁定；真机更慢，那是乐观的一侧），但 FIXSUB/LITFIX/LITAUDIT 三枚旋钮默认全 0 ⇒ 在册实物一字未变。翻默认等的是人眼判决，手上的像素证据是一批 173 个像素（0.352%），按来源拆成 本体侧 74 px（0.151%）与 Link 侧 99 px（0.201%），两块区域不相交、相加正好等于总数。⚠ 这一条先前写的 "Link 侧 48 px（0.098%）"作废：那批只活在 /tmp，配方没记进任何 manifest，不可重算；现在引的是"同一棵 树、只差旋钮"的可复现配方。归因比数量更要紧：按 PNG 整文件 md5 判，单开 FIXSUB 的上屏图与全浮点基准 逐字节相同（房间/Link/本体三条路都验过）⇒ 改画面的只有 LITFIX，"要不要只翻一半"这个选项的代价全在 光照那半。量具能证"最暗处暗一档、173 个全部偏暗"，不能替你决定"这一档换 30 fps 值不值"。判过之后还要按 2026-10-08 那次 LINKTEX 转正的流程重编 67 台在册配方并重拍画面。素材、五台 ROM 的 md5 与重算命令在 evidence/perf/manifest.txt（4x 放大拼图 contact_sheet_2026-10-10_perf4x.png 也在里面），口径见 已知偏差 偏差 9、图见 画面证据。

  • 读数：pA0（本体仍软浮点）11.87 sf/s = 84.3 ms/帧 → pA1（本体整数）39.42 sf/s = 25.4 ms/帧； 参照"整数路 + 摘掉本体"= 39.99 sf/s / 25.0 ms ⇒ 本体绘制从整帧 73% 掉到 1.6%，剩下的账在房间与 Link 之外 也找不到。全软浮点的 550345a4 是 ≈227 ms/帧（旧批次单窗口读数，只作定性）。
  • A/B 两侧都能从树根逐位复现，这是本轮最要紧的一条纪律。 浮点侧的定义是"本体定点化之前"，所以它是 HEAD 那份源码编出来的：git worktree add --detach /tmp/nds_head HEAD 再按同一条命令编，得 dFlo 8bcb631a 与 pA0 4f062fa3，与在册实物逐字节相同。于是"两台只差一处源码"不是叙述，是命令。
  • 逐像素：同机位同钉帧（ANIMSEL=0 ANIMFRAME=10 BOSSSEG=0 BOSSFRAME=8）两台 dFlo / dFix 上屏差 74 px / 49152 = 0.151%，外接框 x[123,146] y[98,130] 整块落在本体剪影里；直方图 Δ8 计 57、Δ9 计 17， 最大单通道差 9，两通道同时不同 19 个。Link 与房间逐位相同这一事实顺带证明两台是同一姿势同一帧（否则 房间像素必动）。Δ9 对着顶点级 lit max 3：glColor3b 的 5 bit 量化步长是 255/31 ≈ 8.2，3/255 的原式色差 跨过一条量化边界就正好是这个量级 —— 不是新的误差源，浮点侧也在同一张网格上。
  • "旋钮全 0 ⇒ 锚点逐位不变"这条纪律，本轮用三种"看着更干净"的写法把它破过一遍（都在 550345a4 上实测）： ① 把一条算术从表达式里提成 int 语句 —— static 且只有一个调用者的函数 gcc 必内联，改的是调用者的栈帧， 613 条指令原地重排；② 为定点表下标引入临时量 —— 经由指针结构体取 R->tri[ti][v] 时索引值从寄存器改走栈槽， 而同一条改写加在定长全局 boss_tri 上不改字节（所以两条路写法不一样不是疏忽）；③ 移动 #include 的位置 —— .text 一字不动，但 .rodata/.bss 的段发射顺序变 94 行。定下的做法是浮点原式只许整段搬进宏 （BOSS_LIT_F / BOSS_NDOT，宏不改调度），两条路各开各的定点表。守的判据也随之改口径："预处理输出逐字符同" 是办不到的（宏名、临时量都在动），真正逐条比的是 diff <(gcc -S 前) <(gcc -S 后) 只差 .file 一行。
  • 判据的输入进库了（evidence/perf/）：两份原始采样序列 .tsv、成对上屏与副屏、一份 manifest.txt。 这是补上一轮的 provenance 缺口 —— 48 px 那批当时只活在 /tmp，/tmp 一清就只剩配方，结论变成不可复核。 ⚠ 这句当日并不成立：那天真正补齐的只有本体那 74 px，Link 侧的 48 px 仍然是两张孤儿图（重核过四个数、 但没有任何命令能重生成它们）。真正的补齐在 2026-10-11，见下一节。 两条重算命令（帧率中位数、逐像素差）都写在 manifest 里，本轮逐字跑通过。
  • 顺带答掉 10-06 那节留的问题（"tools/measure_fps.sh 是删掉还是给 ROM 加一条机器可读输出通道"）： 不需要给 ROM 加宿主通道 —— 副屏 OCR + 周期锁定就够；旧脚本跑不通的直接原因是 tools/ndscrop.py 把进度行走 stdout，那一行混进读数里，于是每次都判"不是数字"、采到 0 个读数。另两条工具的坑（副屏 256 px 宽把 frame 1230 折行、本机 :99 是别人起的 Xvnc 会卡住而不是拒绝）记在 evidence/perf/manifest.txt 末尾。
